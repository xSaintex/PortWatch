{# admin/components/admin_device_form_modal.html Shared modal used for both "Add Device" and "Edit Device". LAYOUT: Two-column Bootstrap grid (col-12 col-md-6) so all fields fit on a 1366×640 laptop without scrolling. Stacks to single column below 768px. ADD mode — opened by the "Add Device" button (data-mode="add"). JS resets the form and sets the action to the add URL. EDIT mode — opened by a row's pencil button (data-mode="edit"). JS prefills every field from data-* attributes on the trigger button. SERVER-SIDE ERRORS (Add only): When validation fails, admin_routes.py re-renders the page with: open_device_modal (bool) — True → JS opens the modal on page load form_errors (dict) — field name → error message form_data (dict) — the values the user originally typed EXPECTS from template context: lab_locations (list of str) — for the Lab datalist autocomplete form_errors (dict) — empty dict on a fresh page form_data (dict) — empty dict on a fresh page open_device_modal (bool) — False on a fresh page #}
{# modal-lg → ~800px wide so the two-column layout has room modal-dialog-centered → vertically centred on screen modal-dialog-scrollable → header + footer stay fixed; only body scrolls This ensures Cancel/Save are never cut off. #}
